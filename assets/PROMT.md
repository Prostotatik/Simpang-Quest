Строим интерактивный веб-прототип 'Simpang Quest' для хакатона CodeNection 2026 (Lifestyle Track, «Planning an Escape»). Референс дизайна — assets/design_reference.png, изучи его очень внимательно, это цель по UI 1-в-1 (кроме названия — на скриншоте лого подписано 'Escape', это старое рабочее название, в реальном приложении везде должно быть 'Simpang Quest', замени лого/заголовок соответственно, остальной стиль и layout — как на скриншоте). Карта-арт для визуала карты — assets/map.png. Единственная цель — красиво и максимально похоже на референс, без багов и лагов. Не нужно ничего оценивать по баллам или сверяться с формальными критериями хакатона — просто ориентируйся на скриншот и делай красиво.

ЭТО ПРОТОТИП. Никакого настоящего бэкенда и никакого настоящего LLM/AI API — ни одного вызова. Единственный реальный внешний сервис — Google Maps JavaScript API, и только для рендера карты (см. ниже). Ключ уже лежит в .env. Все данные о местах — заранее захардкоженный мок-датасет с реальными координатами (не живой геокодинг в рантайме, чтобы демо не зависело от сети/квоты). Состояние приложения только в памяти (React state/store), обновление страницы сбрасывает к сид-данным. Весь текст в интерфейсе — на английском, как в референсе, не переводи на русский.

СТЕК: React + TypeScript + Vite, Tailwind CSS (палитра из референса: пергамент/тёмно-бирюзовый океан/золото), Framer Motion для анимаций, @react-google-maps/api (или @googlemaps/js-api-loader) для карты, лёгкий стор (Zustand или React Context) как единый источник правды для party/trip/сгенерированного маршрута — так, чтобы правки реально триггерили пересчёт.

КАРТА (важнейшая техническая часть):
- Загружай настоящий live Google Maps объект (реальные pan/zoom), но вместо стандартных тайлов рендери assets/map.png как Ground Overlay / custom ImageMapType, привязанный к реальным lat/lng границам полуострова Малайзия (грубо: юг ~1.2°N (Джохор-Бару/Сингапур), север ~6.7°N (граница с Таиландом), запад ~99.5°E, восток ~104.6°E, с запасом под Tioman Island). Откалибруй границы по 3-4 опорным точкам (найди на картинке подписи George Town, Kuala Lumpur, Johor Bahru, Kota Bharu и сопоставь с их настоящими координатами) — это арт, не точная карта, лёгкое смещение нормально, не гонись за пиксель-перфектом.
- Ограничь карту: map.restriction с этими bounds и strictBounds: true, разумные minZoom/maxZoom (чтобы нельзя было улететь за пределы арта или заглянуть на растянутый в пиксели арт), отключи spinning/tilt, отключи стандартные controls (mapTypeControl, streetViewControl, дефолтные POI-лейблы) — пользователь должен видеть только твой арт и кастомные элементы поверх.
- Поверх рисуй кастомные SVG-маркеры в стиле референса (серый '?' = точка на разведке, золотой '?' = найдена, ожидает решения, золотой '!' = подтверждённая точка интереса, серый '!' = не подходит, значок таверны/кубка = еда, значок палатки = привал) и кастомные Polyline: золотой дэш = подтверждённый маршрут (основной путь по confirmed-нодам в оптимальном порядке), серый дэш = альтернативный/разведочный путь до ещё не принятых кандидатов. Легенда как в референсе, внизу карты.

МОК-ДАТАСЕТ POI: создай src/data/pois.ts — 25-30 реальных локаций Малайзии (Langkawi, Penang/George Town, Cameron Highlands, Taman Negara, Kuala Lumpur несколько точек типа KL Tower/Batu Caves/Jalan Alor, Melaka, Johor Bahru, Tioman Island и т.д., покрывающих зону арт-карты), у каждой: id, name, lat, lng, category (poi | food | beach | nature | culture | city), tags[] (nature, active, museums, food, culture, nightlife, adventure, hiking, beaches, art, chill, photography, cities и т.д.), costRM, durationHours, veganFriendly (актуально для category=food), краткое description, картинка-плейсхолдер (можно picsum.photos с seed по id или простой градиент — реальные фото не нужны, это прототип).

ONBOARDING (перед картой):
- Создание party: до 6 персонажей, лист персонажа в духе D&D — имя, возраст, vegan/non-vegan, инвалидность (да/нет), теги интересов (мультиселект из пула тегов выше + возможность добавить свой), свободные даты и диапазон времени в каждой дате, макс. длительность одного приключения (часы), личный бюджет в RM. Можно добавлять/редактировать/удалять участников.
- Trip Details: диапазон дат поездки, общий max duration (дней), общий бюджет (RM, золотые монетки).
- Хочу максимум интерактивности — все поля реально редактируемые, не read-only мок.

ГЛАВНЫЙ ЭКРАН (карта) — воспроизведи 1-в-1 layout референса:
- Левая колонка: Party (список персонажей, клик открывает/редактирует лист) + Trip Details (клик редактирует).
- Центр: карта (описана выше) + внизу горизонтальный скроллируемый ряд карточек кандидатов (POI в статусе 'на разведке', с их иконкой-статусом, тегами, стоимостью, длительностью, клик открывает ту же карточку деталей что и клик по ноде на карте) + Orchestrator-панель (светящийся шар, анимированный, во время генерации/пересчёта крутит моковые фразы reasoning вроде 'Analyzing group preferences...', 'Checking budget & availability...', 'Filtering best routes...', 'Considering weather & risks...', 'Generating itinerary...' — размытый всплывающий текст, красиво анимировано).
- Правая колонка сверху: Quest Journal — список принятых в маршрут точек со статусом (Completed / In Progress / Pending / Skipped), клик по статусу его меняет (это ручной мок-трекинг прогресса поездки, без реального GPS/дат).
- Правая колонка: карточка деталей выбранной ноды — фото, теги, RM, длительность, описание, блок 'Why it's a good fit' с чеклистом причин (выведи причины из скоринга: совпадение тегов, бюджет ok, есть свободная дата и т.д.), кнопка Add to itinerary.
- Forces Majeure: на подтверждённой ноде на карте — иконка тучки. Клик помечает точку закрытой, движок ищет ближайшую похожую альтернативу (похожие теги, укладывается в бюджет, в разумном радиусе) из мок-датасета, показывает карточку 'Forces Majeure' с фото, расстоянием и кнопкой Use Alternative, которая реально заменяет точку в маршруте (Quest Journal и золотой путь на карте обновляются).

RULE-BASED ДВИЖОК (без всякого AI, чистая логика на моковом датасете):
- Скоринг каждой POI против агрегированных предпочтений party: пересечение тегов с интересами участников, бюджетная проходимость (costRM в рамках оставшегося бюджета поездки/на участника), совпадение по vegan/non-vegan для food-точек, попадание в свободные даты/время и в max duration, доступность для участников с инвалидностью (можно простым флагом accessible: boolean у POI).
- По топ-очкам строится маршрут: группировка по дням (исходя из длительности поездки), порядок точек внутри — простой ближайший сосед/жадный алгоритм по реальным координатам.
- Это должно реально пересчитываться при правке party/trip details (дебаунс, кнопка Generate/Regenerate тоже должна работать), а не быть одной зашитой сценой — если я меняю бюджет или снимаю vegan-тег, набор нод на карте должен реально измениться.
- Прогрессив-анимация появления: при (пере)генерации ноды появляются не все разом, а по одной с небольшой задержкой (маленький 'разведчик' идёт от предыдущей точки/оркестратора к новой), сперва как '?', потом резолвится в финальную иконку — имитация 'ИИ агент разведал место', хотя под капотом просто скрипт.
